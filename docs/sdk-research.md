# QuickBooks Desktop SDK research

Research date: October 5, 2026. Primary Intuit pages were read in a rendered browser because their plain HTML responses returned an application shell. Older guide content is distinguished from current support claims. No third-party integration or reverse-engineered file access is used.

## Current architecture and compatibility

Intuit currently lists Desktop SDK **17.0 / installer 17.0.0.1**, with separate x64 and x86 installers. The download page specifies QuickBooks 2024 **R18+** and 2023 **R16+** for its current support statement. The compatibility page describes QBXML 17.0 support for those U.S./Canadian releases and warns that the 64-bit SDK is not backward-compatible with the 32-bit SDK. This does not mean older QBXML query formats disappear. [SDK download](https://developer.intuit.com/app/developer/qbdesktop/docs/get-started/download-and-install-the-sdk), [SDK compatibility](https://developer.intuit.com/app/developer/qbdesktop/docs/get-started/sdk-compatibility-with-quickbooks-releases).

The product matrix lists U.S. 2002–2024, Canadian 2003–2024, UK 2003–2022, excludes Mac, and says the 64-bit SDK integrates with Desktop 2022+. Its historical range describes API compatibility, not a promise of current product support. The page itself contains inconsistent Canadian start years, so do not use its earliest year as a release guarantee. Our first validation target is U.S. QuickBooks 2024 R21; other editions and x86 remain untested. [Product matrix](https://developer.intuit.com/app/developer/qbdesktop/docs/get-started/quickbooks-products-supported-by-the-desktop-sdk).

Desktop integration is local COM plus QBXML request/response messaging. QBFC provides object wrappers and session management over that messaging. We choose direct QBXML behind the adapter: no versioned QBFC runtime dependency and a small, testable parser. This is an implementation choice, not a claim that QBFC is obsolete. [QBFC interface reference](https://static.developer.intuit.com/qbSDK-current/common/newosr/qbsdk/staticHtml/QBFC-QuickRef.html).

## Connection, authorization, running state, and file modes

The documented lifecycle is OpenConnection2 → BeginSession → ProcessRequest → EndSession → CloseConnection. First authorization requires QuickBooks open with the company administrator logged in. Subsequent unattended access is possible if that administrator permits it; the request processor can launch QuickBooks. File modes include single-user, multi-user, and do-not-care. We use do-not-care for these queries. Preferences must be set before BeginSession. [Programmer guide, chapters 4–5 and appendix D](https://static.developer.intuit.com/resources/QBSDK_ProGuide.pdf).

Authorization belongs to each company. Current permissions guidance describes access only while the company is open, access with a prompt, or access even when QuickBooks is not running; sensitive personal information has a separate option. Permissions can be changed/revoked under Integrated Applications. Select attended access for the initial test. Do not interpret unattended permission as proof that a Windows service, Session 0, or every Task Scheduler configuration will work. Those deployment combinations require separate testing. [Current Intuit permissions guidance](https://quickbooks.intuit.com/learn-support/en-us/help-article/security-access/block-applications-accessing-quickbooks-company/L7JM4Ms8o_US_en_US).

The current implementation requests PutIsReadOnly(false), PutPersonalDataPref(pdpRequired=1) and PutUnattendedModePref(umpRequired=1) for every session, per the user's explicit request to avoid changing permission profiles. The stable identity is McMurry Software QuickBooks CLI; no forced-authorization flag is set. CLI mutations independently require --apply, an explicit company path and schema validation. This replaces the initial read-only preference. Authorization succeeded on the test PC; unattended execution with QuickBooks fully shut down remains unverified.

Read queries do not request a switch into single-user mode. Other SDK operations may require that mode, and an incompatible already-open file/session can prevent BeginSession. Attended/multi-user, a closed file after unattended approval, different Windows accounts, and permission refusal/revocation are separate acceptance cases. Do not open a production file to resolve a test failure.

## COM and .NET

This PC's installed public COM registration reports `ThreadingModel=Apartment` for `QBXMLRP2.RequestProcessor`. Its Intuit type library exports IRequestProcessor3–6, IAuthPreferences, and enum definitions. This is documented public interface metadata, not examination of company-file internals. The CLI runs on an STA main thread, keeps calls and releases on that thread, and uses explicit IDispatch interface projections. The initial late-binding probe failed with 0x80020006 when accessing AuthPreferences; binding IRequestProcessor4 solved it. Preferences shared the processor RCW identity, so releasing that RCW immediately invalidated the processor. The adapter now avoids releasing the shared identity until session cleanup.

Verified local constants: localQBD=1, qbFileOpenDoNotCare=2, pdpNotNeeded=3. Verified interface GUIDs and DISPIDs are recorded in ComRequestProcessor.cs. Only members needed for the milestone are projected; the full SDK is not vendored. .NET 10 COM activation, preferences, BeginSession, both query requests, and cleanup are verified against the authorized local test file. Three additional pairs of company/account sessions succeeded.

Publish separately for win-x64 and win-x86. In-process COM activation depends on registration in the matching architecture. Do not infer that running on 64-bit Windows makes an x86 request processor available to an x64 process. The x86 build is an exploratory target until tested with an appropriate legacy installation. This PC has QuickBooks Premier Accountant 2024 executable version **34.0D R21** and an x64 request processor.

## Queries, data boundaries, and limitations

CompanyQuery and AccountQuery are documented reads. CompanyName/LegalCompanyName and account IsActive are optional: preserve missing values as JSON null rather than inventing them. IncludeRetElement narrows responses to DTO fields. AccountQuery's published schema has MaxReturned but no iterator; omit MaxReturned for a complete initial chart of accounts. Account types remain readable strings; IDs are opaque and scoped to the company. Exact numeric-name account lookup has a documented account-number ambiguity, relevant before implementing `accounts get --name`. [CompanyQuery](https://developer.intuit.com/app/developer/qbdesktop/docs/api-reference/qbdesktop/companyquery), [AccountQuery](https://developer.intuit.com/app/developer/qbdesktop/docs/api-reference/qbdesktop/accountquery).

The parser rejects unexpected response types, malformed XML, external entities, missing required account identity fields, and incomplete responses. SDK warnings fail visibly. Status 1 (no match) with an empty account response is a successful empty list. Responses have a 32 MiB parser limit; this is an intentional POC bound, not an SDK size limit. SDK report results will require explicit normalization of columns, dates, accounting basis, and totals before becoming a stable JSON contract.

## Installation and commercial distribution

For this direct-adapter approach the test PC needs a licensed, activated Desktop installation and its correctly registered request processor. The full SDK is useful on a development/test PC for SDKTestPlus3, OSR/schema documentation and comparison, but our executable does not link QBFC or require the full SDK installation. Use the official SDK installer when those tools are needed; downloads require an Intuit Developer login. Never bundle the request processor DLL. [SDK download](https://developer.intuit.com/app/developer/qbdesktop/docs/get-started/download-and-install-the-sdk), [redistribution guidance](https://developer.intuit.com/app/developer/qbdesktop/docs/go-live/redistributing-sdk-components-with-your-application).

Intuit's redistribution page permits the supplied component installers/merge modules and prohibits copying raw request-processor DLLs. QBFC redistribution must use the supplied supported packaging if we adopt it later. Some details on that page describe very old Windows/QBFC releases; verify the selected SDK's actual packaging and license rather than following those old dependency recipes. We ship only our binaries and the .NET self-contained runtime, with no Intuit DLLs. [Redistribution guidance](https://developer.intuit.com/app/developer/qbdesktop/docs/go-live/redistributing-sdk-components-with-your-application).

Commercial Desktop integrations are contemplated by Intuit's marketplace documentation: listing requires review, SDK integration, branding compliance, supported Windows, and compatibility with a recent Desktop release. Its FAQ says customers are redirected to the developer's own website for purchases. These are listing requirements, not a blanket license grant for any distribution. [Go-live FAQ](https://developer.intuit.com/app/developer/qbdesktop/docs/go-live/faqs).

**Unresolved commercial release prerequisite:** obtain and review the current SDK 17 installer license/qbXML license and applicable developer agreement; confirm the conditions for distributing this standalone commercial CLI and any copied interface declarations. The full SDK is not installed here and its authenticated installer was not downloaded or accepted. Do not claim fees, redistribution rights, certification exemptions or unlimited runtime-user rights from old documentation. Intuit's legal index separately links developer-services terms and the Desktop EULA. The Desktop customer license does not replace the SDK agreement. [Legal index](https://www.intuit.com/legal/terms/), [Desktop 2024 U.S. EULA](https://www.intuit.com/legal/terms/en-us/quickbooks/desktop-payroll-2024/).

# Discovery and bulk processing research — 2026-10-05

The [SDK Programmer Guide](https://static.developer.intuit.com/resources/QBSDK_ProGuide.pdf) documents multiple requests per message set, requestID response correlation, session-scoped query iterators, stopOnError/continueOnError and message-set error recovery. These support batching; they do not provide atomic rollback or a universal transaction reclassification operation. Appendix A lists status 1 (no matching query object) and 500 (required object not found). A single explicit customer/vendor lookup with an empty 500/Warn response is reported as not_found; paged/broad warnings are still failures.

Rendered [CustomerQuery](https://developer.intuit.com/app/developer/qbdesktop/docs/api-reference/qbdesktop/customerquery), [VendorQuery](https://developer.intuit.com/app/developer/qbdesktop/docs/api-reference/qbdesktop/vendorquery) and [HostQuery](https://developer.intuit.com/app/developer/qbdesktop/docs/api-reference/qbdesktop/hostquery) references informed the new allowlisted reads. Customer/vendor iterators start at qbXML 5.0; the current field set uses 6.0. Continuations repeat IncludeRetElement and keep filters consistent. Exact ListID/FullName lookup and filtered pagination are different schema alternatives.

The API reference navigation yielded 239 operation names and optional version annotations. Embedded sdk-operations.txt preserves that snapshot. An absent annotation remains unknown; catalog presence alone proves neither edition support nor authorization. Operation field-level schemas and transaction-class modification coverage are future work, not silently inferred from the sidebar.
